# デザイン規約

トークン値・コンポーネント仕様の正は `docs/DESIGN_SYSTEM.md`。ここに値を複製しない。

## トークン

- 色・余白・フォントは `src/styles/` のデザイントークン（CSS変数 / Tailwind テーマ）経由で使う。HEX値・任意値（`text-[#...]`）を直書きしない。
- ライト / ダーク両方のトークンを必ず定義する。新しい色が必要ならトークンを追加し、DESIGN_SYSTEM.md を更新する。
- 記事ごとに独自デザインを作らない。サイト共通コンポーネントを使う。

## レイアウト

- 本文最大幅・ヘッダー高さ・3カラムグリッド・ブレークポイント（TOC折りたたみ、サイドバーのドロワー化）は DESIGN_SYSTEM.md の値に従う。
- ページ全体の横スクロールを発生させない。表・コード・数式は個別にスクロール可能なラッパーに入れる。
- テーマ（light / dark / system）はハイドレーション前のインラインスクリプトで適用し、ちらつきを出さない。

## アクセシビリティ（WCAG 2.2 AA 目標）

- テキストのコントラスト比 4.5:1 以上（大きい文字 3:1）。両テーマで確認する。
- 色だけで意味を伝えない。コールアウトは「アイコン＋ラベル文字」。難易度は図形＋文字。
- すべての操作をキーボードで可能に。フォーカスリングを消さない。ドロワーは Esc で閉じ、フォーカスを戻す。
- ランドマーク（header / nav / main / aside）と見出し階層を正しく使う。アイコンのみのボタンには `aria-label`。
- `<html lang="ja">` を維持する。

## 避けるもの

- 過剰なカード、グラデーション、アニメーション、影の多用。
- 絵文字によるセクション装飾。
- 未公開カテゴリのサイドバー表示、未執筆記事の大量表示。

## 確認

- UIを変更したら `visual-reviewer` でライト / ダーク / モバイル幅のスクリーンショットを確認する。
