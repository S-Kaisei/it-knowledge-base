# 0011. 図の配置・覚え方・IPA 過去問を記事構成に加える

- ステータス：Accepted
- 日付：2026-11-28

## コンテキスト

- SPEC §8 の標準構成には独立した「図解」の見出しがあり、確認問題は任意としていた。
- 15 本を公開したあと、プロジェクトオーナーから既存記事も含めて次の 3 点の要望があった。
  1. 図解やシミュレーターは、説明から離れた「図解」セクションにまとめず、理解の助けになる位置に置く。
  2. どう覚えればよいか（覚え方）を説明の中に含める。図やシミュレーターを説明の途中に置くことも、その手段の一つとする。
  3. 記事の最後に、関連する過去問を 10 問載せる。
- SPEC §18 と CONTENT_GUIDE §4 は「第三者の文章・図解・問題集を無断転載しない」と定めている。
- IPA の FAQ（<https://www.ipa.go.jp/shiken/faq.html>、2026-11-28 確認）には、次の記述がある。
  - 公表している過去の試験問題の使用には、法令に特別の定めがある場合を除き、許諾も使用料も要らない。
  - 出典（年度、期、試験区分、時間区分、問番号等）を明記する。例：「出典：平成31年度 春期 基本情報技術者試験 午前 問1」。
  - 問題の一部を改変した場合は、その旨も明記する。
  - 著作権は放棄していない。
  - 公表している PDF 以外の電子データは提供しない。
- 問題 PDF はコピーが許可されていない（PDF のセキュリティ設定）。

## 決定

- **図・シミュレーター**：独立した「図解」見出しを標準構成から外す。図・表・シミュレーターは、それが説明する段落の直前または直後に置く。図を本文でも説明するという規則は維持する。
- **覚え方**：仕組みの説明の中に、覚え方を `<Callout type="tip" title="覚え方">` で入れる。書くのは、理屈で覚えるための手がかりである。具体的には、因果関係・対比・数値の導き方・図との対応などを使う。根拠のない語呂合わせだけにはしない。
- **IPA 過去問**：記事末尾の見出し「過去問題」に、関連する IPA 情報処理技術者試験の過去問を **10 問を目標**に載せる。
  - 問題文と選択肢は、IPA が公表している問題 PDF を目で見て**打ち直し、全文を掲載する**。コピー保護を技術的に解除したり回避したりしない。PDF をページ画像として表示して読むことは可とする。
  - 出典は IPA の FAQ の形式で書く（`PastExam` の `source`）。問題文を改変した場合は `modified` を付けて「（一部改変）」と表示する。
  - 正解は IPA の解答例 PDF で確認する。解説は自分の言葉で書き、折りたたみで表示する（`PastExamAnswer`）。
  - 候補を探すときは第三者の索引を使ってよい。ただし、掲載する問題文と正解の根拠は必ず IPA の PDF とする。第三者の解説文は転載しない。
  - 関連する過去問が 10 問に満たない分野では、関係の薄い問題で数を埋めない。見つかった分だけを載せ、「現時点で関連する過去問は N 問」と明記する。
  - 既存の自作「理解度チェック」は残し、その後に「過去問題」を置く。
- **規約の例外**：SPEC §18 の「問題集を無断転載しない」との関係を明確にする。IPA の過去問は、IPA が許諾不要と公表している範囲内でのみ、上の条件を満たして使う。IPA 以外の問題集・過去問サイトの問題と解説は、従来どおり転載しない。
- **検証**：`content:check` で次の項目を機械的に検証する。
  - `source` の形式
  - 正解が 1 つあること
  - 記事内で `source` が重複しないこと
  - 公開記事で過去問が 10 問未満のときの警告
- **レビュー**：独立レビューでは次の 3 点を確認する。問題文が PDF と一致しているか、正解が解答例と一致しているか、記事との関連が妥当か。

## 理由

- 図を説明の近くに置くと、読者は本文と図を行き来せずに済み、理解と記憶につながる。
- 試験対策を兼ねる読者にとって、本文の知識が実際の出題形式でどう問われるかを確認できる価値は大きい。
- IPA が出典を明記したうえでの使用を許諾不要と明示しているため、条件を守れば権利上の問題はない。
- 打ち直した全文を載せる方式は、出典とリンクだけを載せる方式より読者の手間が少ない。オーナーもこの方式を選んだ。

## 代替案

- **出典・正解・要点だけを載せ、問題文は IPA の PDF へのリンクにする**：権利上は最も安全だが、読者が PDF を探して開く必要があるため採用しない。
- **問題の趣旨を自分の言葉で要約して載せる**：改変の範囲が大きくなり、実際の出題形式の練習にならないため採用しない。
- **関連の薄い問題で必ず 10 問にそろえる**：記事との関連が弱い問題は学習効果が低く、読者を誤解させるため採用しない。

## 影響

- SPEC §8 の標準構成の「図解」見出しと「理解度確認問題（任意）」は、この ADR の内容に置き換わる（SPEC 本文は変更せず、本 ADR で記録する）。
- `docs/CONTENT_GUIDE.md`、`docs/templates/article.md`、`.claude/rules/content.md`、`.claude/rules/security.md`、add-topic スキル、technical-writer と technical-reviewer エージェントを更新する。
- `PastExam` / `PastExamAnswer` コンポーネントと `content:check` の検証を追加する。
- 既存の公開記事 15 本を順次改修する。改修は記事ごとに独立レビューを通してから公開する。
- 過去問の打ち直しには誤記のリスクがあるため、レビュー時に PDF のページ画像と突き合わせる。
